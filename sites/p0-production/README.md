# MOX-ADV P0 for GPT Sites

Private GPT Sites production candidate for the first MOX-ADV campaign workflow.

The Context step verifies the exact configured Yandex Direct advertiser through official `clients.get` and the exact Yandex Metrika counter and goal through official Management APIs before it permits progress. It then researches only a DNS-verified public first-party HTTPS target with manual redirect handling, a four-redirect cap, at most six pages and a 5 MB streamed-response budget. Private/local/link-local resolutions, credential-bearing URLs, cross-party redirects and oversized responses fail closed. Before the longer Model analysis starts, the step persists the sanitized API/site facts and exactly one evidence-grounded provisional business goal; the owner must explicitly confirm or correct it.

The Site keeps all OAuth credentials server-side and persists revisioned state in D1. The Model step emits one deeply immutable, content-addressed `p0-analytics-evidence-v2` snapshot with separately hashed source manifests, normalized claims, typed Evidence Records, bounded/redacted raw locators and values, transforms, versions, timestamps, conflicts and explicit gaps. First-party public observations, owner confirmations, official Direct API evidence, official Metrika API evidence and allowlisted public competitor observations remain distinct. Confidence stays a quality/freshness/consistency/coverage/uncertainty vector; Metrika sampling/privacy/lag and Direct read limitations remain attached, and unavailable current Direct inventory is a material blocker rather than zero activity. Competitor budgets, CPC, conversions, account state and internal strategy remain unavailable by policy. The same snapshot now persists official Wordstat `/v1/topRequests`, `/v1/dynamics` and `/v1/regions` observations under one batch identity with explicit operator/region/device scope. Unique assigned rows are summed once and labelled `LOWER_BOUND_OBSERVED_TOP_ROWS`; missing rows, partial responses, quota and provider failures remain `PARTIAL`/`UNAVAILABLE`, never zero. Pre-launch cost selects the first qualified source in strict Live 4 → comparable existing KeywordBids → comparable own-history order without averaging and otherwise remains explicitly unavailable. The production adapter verifies normalized phrase identity through official `Keywords.get` before reading `KeywordBids.get`; unavailable Live 4 capability/history and `AuctionBids=null` stay named unavailable observations rather than zero CPC. Campaign Strategy compiles the persisted Demand Clusters into deterministic delivery buckets across goal, economics, geography, landing, message and management; compatible long-tail is packed, while a material split requires evidence-backed standalone capacity. One immutable Campaign Strategy revision deterministically produces a finite Recommendation Set of materially distinct, fingerprinted Campaign Drafts with audited hidden candidates; the current publish path fixes one selected exact projection while the shortlist/package interaction is refined separately. After one exact Human Decision Gate it creates the real Direct object graph through v501, explicitly calls `Campaigns.suspend`, requires `State=SUSPENDED` before any child write, submits the ad for moderation, and repeats the suspended readback. `Campaigns.resume` is not implemented.

`lib/p0-application.ts` is the authoritative `mox-adv.p0.application` query/command contract for the five-step path. `GET /api/p0` queries the contract and `POST /api/p0` sends a command with `expected_revision`; both Sites rendering and future Dashboard rendering consume the returned workflow truth table instead of deriving transitions from document fields. The contract owns the persisted document, including exactly one top-level `analytics_evidence_snapshot`, Campaign Strategy, Recommendation Set, Campaign Draft and external outcome. Queries reuse that persisted snapshot and never recompute evidence from a newer provider read. A new evidence result requires a Model command and a new document revision. Baseline v1 documents migrate their nested snapshot to the single v2 document field without creating another evidence store; legacy and current content hashes are verified before query reuse or downstream recommendations. Every successful migration or command advances one monotonic document revision through compare-and-swap; the exact external-write intent is CAS-persisted before any provider mutation and the outcome advances it again. `analyze_site` persists provisional Context, and `confirm_context_goal` records the explicit owner decision before full analysis. A material Context edit records the affected Strategy, Recommendation Set, Campaign Draft, shortlist and confirmation lineage, clears those current projections and blocks confirmation until recomputation; normalization-only URL/whitespace changes do not create false invalidation. Evidence and scoring returned for a revision come from that persisted document rather than being recomputed during a query. Legacy Sites documents are upgraded only when their lineage can be reconstructed; malformed, unknown-schema or orphaned-outcome documents fail explicitly without being overwritten. Public research uses credential-free GET, manual redirects, DNS/IP checks, exact host allowlists for competitor pages and fail-closed redirect/SSRF/size limits. Snapshot, client and persisted artifacts redact credential and common PII patterns; no prompt, token, browser-cabinet data or model chain of thought belongs in the document. Production Wordstat collection uses the separate server-side `YANDEX_WORDSTAT_OAUTH_TOKEN` and registered `YANDEX_WORDSTAT_CLIENT_ID`, plus explicit comma-aligned `YANDEX_WORDSTAT_REGION_IDS`/`YANDEX_WORDSTAT_REGION_NAMES` and `YANDEX_WORDSTAT_DEVICE`; only `POST` calls to `api.wordstat.yandex.net` are allowed, and credentials never enter the batch or client state.
