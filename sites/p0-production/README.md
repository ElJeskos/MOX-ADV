# MOX-ADV P0 for GPT Sites

Private GPT Sites production candidate for the first MOX-ADV campaign workflow.

The Site reads the connected Yandex Direct account and Yandex Metrika goal through server-side production credentials, researches a user-selected first-party HTTPS site, and persists revisioned state in D1. The Model step emits a versioned analytics evidence snapshot with primary-source lineage, a confidence vector, explicit coverage gaps, and an unavailable pre-launch cost whenever no comparable first-party history exists; it never invents competitor or Wordstat evidence. One immutable Campaign Strategy revision deterministically produces a finite Recommendation Set of materially distinct, fingerprinted Campaign Drafts with audited hidden candidates; the current publish path fixes one selected exact projection while the shortlist/package interaction is refined separately. After one exact Human Decision Gate it creates the real Direct object graph through v501, explicitly calls `Campaigns.suspend`, requires `State=SUSPENDED` before any child write, submits the ad for moderation, and repeats the suspended readback. `Campaigns.resume` is not implemented.

`lib/p0-application.ts` is the authoritative `mox-adv.p0.application` query/command contract for the five-step path. `GET /api/p0` queries the contract and `POST /api/p0` sends a command with `expected_revision`; both Sites rendering and future Dashboard rendering consume the returned workflow truth table instead of deriving transitions from document fields. The contract owns the persisted document, Analytics Evidence Snapshot lineage, Campaign Strategy, Recommendation Set, Campaign Draft and external outcome. Every successful migration or command advances one monotonic document revision through compare-and-swap; the exact external-write intent is CAS-persisted before any provider mutation and the outcome advances it again. Evidence and scoring returned for a revision come from that persisted document rather than being recomputed during a query. Legacy Sites documents are upgraded only when their lineage can be reconstructed; malformed, unknown-schema or orphaned-outcome documents fail explicitly without being overwritten.
