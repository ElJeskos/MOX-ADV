# MOX-ADV P0 for GPT Sites

Private GPT Sites production candidate for the first MOX-ADV campaign workflow.

The Context step verifies the exact configured Yandex Direct advertiser through official `clients.get` and the exact Yandex Metrika counter and goal through official Management APIs before it permits progress. It then researches only a DNS-verified public first-party HTTPS target with manual redirect handling, a four-redirect cap, at most six pages and a 5 MB streamed-response budget. Private/local/link-local resolutions, credential-bearing URLs, cross-party redirects and oversized responses fail closed. Before the longer Model analysis starts, the step persists the sanitized API/site facts and exactly one evidence-grounded provisional business goal; the owner must explicitly confirm or correct it.

The Site keeps all OAuth credentials server-side and persists revisioned state in D1. The Model step emits a versioned analytics evidence snapshot with primary-source lineage, a confidence vector, explicit coverage gaps, and an unavailable pre-launch cost whenever no comparable first-party history exists; it never invents competitor or Wordstat evidence. One immutable Campaign Strategy revision deterministically produces a finite Recommendation Set of materially distinct, fingerprinted Campaign Drafts with audited hidden candidates; the current publish path fixes one selected exact projection while the shortlist/package interaction is refined separately. After one exact Human Decision Gate it creates the real Direct object graph through v501, explicitly calls `Campaigns.suspend`, requires `State=SUSPENDED` before any child write, submits the ad for moderation, and repeats the suspended readback. `Campaigns.resume` is not implemented.

`lib/p0-application.ts` is the authoritative `mox-adv.p0.application` query/command contract for the five-step path. `GET /api/p0` queries the contract and `POST /api/p0` sends a command with `expected_revision`; both Sites rendering and future Dashboard rendering consume the returned workflow truth table instead of deriving transitions from document fields. The contract owns the persisted document, Analytics Evidence Snapshot lineage, Campaign Strategy, Recommendation Set, Campaign Draft and external outcome. Every successful migration or command advances one monotonic document revision through compare-and-swap; the exact external-write intent is CAS-persisted before any provider mutation and the outcome advances it again. `analyze_site` persists provisional Context, and `confirm_context_goal` records the explicit owner decision before full analysis. A material Context edit records the affected Strategy, Recommendation Set, Campaign Draft, shortlist and confirmation lineage, clears those current projections and blocks confirmation until recomputation; normalization-only URL/whitespace changes do not create false invalidation. Evidence and scoring returned for a revision come from that persisted document rather than being recomputed during a query. Legacy Sites documents are upgraded only when their lineage can be reconstructed; malformed, unknown-schema or orphaned-outcome documents fail explicitly without being overwritten.
